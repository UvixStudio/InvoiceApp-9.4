## ⚠️ הערה קריטית – startingRow

אל תקבע `startingRow = 14` קשיח.  
התחלת הכתיבה צריכה להיות **דינאמית**, כדי לא לדרוס נתונים קיימים בסריקות נוספות לאותו גיליון.

### במקום
```js
const startingRow = 14;
```

### השתמש ב
```js
const startingRow = findLastRowWithData(sheet) + 1;
```

### הסבר
- בריצה הראשונה על גיליון חדש – יש רק Mini-Log (1–11), רווח (12), כותרות (13), ואז `startingRow = 14` ✔️  
- בריצה שנייה או שלישית – הוא תמיד יתחיל אחרי השורה האחרונה שיש בה דאטה, ולא ידרוס רשומות קודמות ✔️

## 🧭 שאר ההנחיות המאושרות

### ✅ Mini-Log
- טווח קבוע: **F1–G11**
- מנוהל מתוך `processInvoices` ו־`processEmails` בלבד (לא מתוך `createOrUpdateResultsSheet`).
- מתעדכן לייב בזמן הסריקה:
  - `F3`: זמן התחלה  
  - `F5`: כמות מיילים שנמצאו  
  - `F6–F8`: התקדמות  
  - `F9`: תוצאות סופיות

### ✅ כותרות הטבלה
- בשורה **13**
- הקפאת 13 שורות ראשונות (`sheet.setFrozenRows(13)`)
- רשומות חדשות נכתבות מתחת לשורה האחרונה הקיימת (לפי `findLastRowWithData`)

### ✅ Toasts
- למחוק את כל ה־toasts מתוך `processInvoices` ו־`processEmails`  
- להשאיר **רק טוסט אחד קצר (5 שניות)** בסוף הסריקה (`showScanSummary`)

### ✅ Batch Write
- כתיבה מרוכזת אחת בלבד לכל הסריקה.  
- אין `setValues` או `flush` בלולאה.
- צ׳קבוקסים נכתבים רק בסוף.

### ✅ prepareDownloadLinksForSelected
- החלפת הלוגיקה ל־Batch Write מלא.  
- שימוש ב־`gmailCache` כדי למנוע פניות חוזרות ל־Gmail.  
- עדכון על המערך `data` בלבד, וקריאת `setValues` אחת בסוף.  
- דילוג על שורות 1–13 (Mini-Log + כותרות).  
- `alert` אחד בסיום בלבד, בלי טוסטים.
